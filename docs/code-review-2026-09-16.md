## 场景／值（长表方式）是否有用

有用，两者配套使用，把 `月份 / 场景 / 金额` 转成各场景系列。例如：

| 月份 | 场景 | 金额 |
| --- | --- | ---: |
| 202601 | AC | 100 |
| 202601 | PY | 80 |

对应字段绑定为：月份 → 时间轴，场景 → 场景，金额度量 → 值。不需要再绑定专用 AC/PY 字段。

截图采用专用度量方式：时间轴 + AC + PY；场景为空。因此“值”中的重复销售额度量对柱形数值没有贡献，可以从该报表的字段槽移除。解析器在存在任一专用场景度量时优先使用专用度量（src/dataModel.ts:142）。但目前闲置“值”仍可能影响数字格式，见问题 4。

结论：不符合“没用就删除”的条件，保留长表功能。建议把专用 AC/PY/PL/FC 字段排在前面，把长表字段放后面，并明确提示“两种方式二选一”；混合绑定时显示提示，避免静默忽略。没有操作用户的 PBIX，也没有替用户移除截图里的绑定。

## 已确认的问题（按修复优先级）

### 1. P1：瀑布图漏掉缺少对比值的类别，终点不再是完整实际合计

- 位置：src/visual.ts:607。
- 条件：A 的 AC=100/PY=80，B 的 AC=50/PY=null。
- 复现结果：瀑布显示 PY=80、A 的差异=20、AC=100，B 被完全跳过；实际 AC 合计应为 150。表格的 computeTotals 会独立累计两侧，因此两种模式口径不一致。
- 建议：保留完整两侧合计；对缺失基准明确选择缺失处理策略，用单列调整或可识别的缺失提示衔接。不要无提示地把可比样本合计标成总体 AC，也不要默认把所有缺失值当零。

### 2. P1：横向方差图不正确绘制负实际值

- 位置：src/renderers/varianceChart.ts:121、292；合计同样受影响（541）。
- 条件：AC=-100、-50。
- 复现结果：两根 AC 横条都为 1.5px，无法体现方向及 2:1 的大小关系。当前比例尺只考虑正数。
- 建议：改为包含负数和零点的线性比例尺，使用零点到数据值的距离绘制条形；同步处理合计、标签和断轴标记。

### 3. P1：时间序列用显示文本作横轴键，独立数据点可能重叠

- 位置：src/renderers/timeSeries.ts:57。
- 条件：两个不同选择身份具有相同显示标签（例如两个不同类别都叫 Central；同名时间成员也有同样风险）。解析层已经正确保留两条记录。
- 复现结果：两个 AC 柱的 x 都为 250.9056，彼此覆盖。
- 建议：横轴使用唯一身份或稳定序号，文本仅用于标签，和纵向方差图现有的独立槽位处理保持一致。

### 4. P2：闲置“值”字段覆盖正在使用的 AC 数字格式

- 位置：src/dataModel.ts:277。
- 条件：AC 金额格式为 `#,0`，同时把百分比度量放进长表“值”，但没有场景字段。
- 复现结果：scenarioSource 为 measures，valueFormat 却为 `0.0%`；销售金额会交给百分比格式器处理。
- 建议：按实际生效的输入方式选择格式；进一步按场景保留格式，避免一个格式串强制用于全部场景。

### 5. P2：多基准面板分别排序，破坏跨面板类别对齐

- 位置：src/visual.ts:510。
- 条件：A/B 的 AC 都为 100；PY 为 0/90；PL 为 99/0；全部基准模式下按差异降序。
- 复现结果：PY 面板顺序 A/B，PL 面板顺序 B/A。画布较小时，各面板还可能截出不同的可见类别。
- 建议：确定一个主基准后只排序一次，各面板复用相同顺序；如提供独立排序，应明确标识。

### 6. P2：Top N 的“其他”直接相加任意度量和工具提示

- 位置：src/visual.ts:438–449；合计逻辑另见 src/renderers/common.ts:252。
- 静态检查确认对数值直接求和，没有指标可加性判断。例如毛利率 20% 与 30% 会在“其他”提示里变成 50%；去重门店数等也不能按类别简单累加。
- 建议：对非可加指标不显示客户端合计，或通过模型提供正确聚合结果；工具提示不要默认求和所有度量。

## 与 Zebra BI 官方的主要差距

| 优先级 | 当前实现 | 官方能力与建议 |
| --- | --- | --- |
| 高 | 时间序列只有场景柱叠加；基准和差异开关没有接入此渲染器 | 增加时间序列绝对/相对差异组合，避免只能切到另一种图表看差异。[官方图表概览](https://help.zebrabi.com/kb/power-bi/overview-of-chart-types-in-the-zebra-bi-charts-visual/) |
| 高 | 所有非空 AC/FC 同时绘制，没有实际截止期判断 | 支持 AC 截止后接续 FC 的分段时间序列，并标出预测区间。[官方预测说明](https://help.zebrabi.com/kb/power-bi/overview-of-chart-types-in-the-zebra-bi-charts-visual/) |
| 高 | 类别/时间各限一个字段，无 drilldown 映射；类别与时间同时输入时分别汇总 | 增加年→季→月、组织层级下钻；增加按业务维度分组的小多图，不能把现有“多基准面板”视为业务分组小多图。[官方层级与小多图](https://help.zebrabi.com/kb/power-bi/overview-of-chart-types-in-the-zebra-bi-charts-visual/) |
| 中 | 时间序列只稀疏化轴标签，AC 数值标签仍全量显示；拥挤时会相互覆盖；每次重建图内所有节点 | 增加数值标签碰撞检测、图例换行、空间不足时的布局降级；大数据量采用可见窗口与节点复用。官方强调自适应布局。[官方 Charts](https://zebrabi.com/power-bi-custom-visuals/charts/) |
| 中 | 场景名称仅手工指定或回退 AC/PY/PL/FC；已解析的 measureNames/scenarioDisplay 没有用于默认图例 | 增加度量名/场景名驱动的动态图例。截图中 PY 实际放的是“上周”度量，默认 PY 容易误读；当前可先手工改成“上周”。[官方动态图例](https://zebrabi.com/product-update/dynamic-chart-legends-power-bi/) |
| 中 | 瀑布只有起点、增量、终点，没有用户指定中间小计和单项方向反转 | 补齐财务桥图所需的小计、结果列与单项反转。[官方瀑布说明](https://help.zebrabi.com/kb/power-bi/overview-of-chart-types-in-the-zebra-bi-charts-visual/) |
| 后续 | 五种固定模式，表格为单层行数据；每个 PL/FC 只允许一个度量 | 视需求增加组合图、多个计划/预测及层级表格。Zebra BI Tables 是独立产品，不能仅因有语义表格模式就认为已经达到 Tables 的覆盖范围。[官方多计划/预测](https://help.zebrabi.com/kb/power-bi/support-multiple-forecasts-and-multiple-plans/) |
